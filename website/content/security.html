Security

In plain words: what protects your data, and what does not.

Login

  • One password, stored as a bcrypt hash.
  • Optional two-step login with an authenticator app and recovery codes. Optionally trust a browser for 30 days to skip the code (never the password); Trust This Browser is never ticked for you.
  • Five wrong tries pause logins for 15 minutes, doubling up to a day.
  • Sessions last 30 days, are tied to the browser, and use HttpOnly and SameSite=Strict cookies (Secure on HTTPS). Changing the password or choosing Log out other devices ends every other login.
  • Every change after login needs a security token, and requests from other websites are refused.

Encryption

One passphrase locks Info's encrypted tabs, Links' encrypted tabs and backup files. Keys are made in your browser and wrapped with the passphrase (PBKDF2, 600,000 rounds); backup files use PBKDF2 with 310,000 rounds and AES-256-GCM. A lost passphrase and a lost recovery key mean lost data.

Your data

Data lives in site-data inside the site folder, locked three ways: a deny-all .htaccess, an empty index file, and data files that are PHP files answering 404 in a browser even on a server that ignores .htaccess. Nothing in site-data can run as a script.

Tools

  • Every tool runs in your browser. Files you open are not uploaded; the engines (OCR, background removal, the QR reader) are shipped with your site and nothing is fetched from another website.
  • The camera, the microphone and screen sharing are allowed on the Tools page only, and only after you press the scanner's or the recorder's button; your browser asks first. Every other page refuses them.
  • Saved presets (a signature, a watermark, your business details) are kept on your server only while you are logged in, inside site-data. Each one is checked: plain values only, pictures only as images stored in the preset itself, and no web addresses, so a preset can never point your browser anywhere.

How updates are checked

  1. The site contacts only GitHub hosts, over HTTPS, and checks every redirect.
  2. The download is compared with the size and SHA-256 listed for that release. This catches damaged or partial downloads.
  3. The zip then gets the same full check as an uploaded one: safe names, every file whole, PHP files readable, a newer version, room on the disk.
  4. Nothing installs until you read the changes and type your password. A snapshot is taken first, and the site rolls back on its own if it cannot answer afterwards.

The daily check is off by default. While it is off the site makes no request to GitHub unless you press Check Now.

Reporting a problem

To report a problem, open an issue. For anything else, message @Jackpison on Telegram. The security policy says what is in scope and which versions get fixes (the latest release only).
